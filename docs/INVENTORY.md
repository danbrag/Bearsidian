# CSS inventory and preservation decisions

The initial import inspected all custom snippet CSS in the primary vault, two other registered vaults, and the reusable template. Theme and plugin styles were inspected as compatibility context; their stylesheets are not bundled.

- `bear-dark-sidebar.css`: application chrome, both dark sidebars, file explorer, vault controls, tabs, light editor surfaces, ribbons, titlebar/status bar, Editing Toolbar geometry and six dark highlight colors.
- `sidebar-text-size.css`: 14px file/folder labels, native folder caret replacement, Iconic folder/file icon sizing and offsets, extra title spacing, and 15px tree edge padding.
- `focus-dimming.css`: excluded at the owner's request; remains a separate snippet.
- Other available copies: tree CSS is identical. Template/test chrome CSS is an older copy missing only toolbar and highlighter rules. The third registered vault has only Focus Mode dimming. No additional unique Bear customization was found.

## Cascade decisions

Preserve source order (chrome first, tree alignment second). Remove earlier declarations only when the same selector/property has a later declaration of equal or higher importance. Split grouped selector lists only as needed to retain their unaffected members. This removes demonstrable duplication and supersession without assuming different selectors are interchangeable.

The later `:root` palette is retained: it cannot override explicit `body` custom properties, although it applies at the document root. Moving its values to `body` would change the working palette. The light editor variable is also defined on `.theme-light` and must keep that specificity.

Broad backgrounds followed by transparent tab backgrounds, muted toolbar icons followed by final icon polish, right search-match normal text followed by muted text, and repeated ribbon/empty-editor fixes reflect successive tuning. Only exact-selector supersession is removed; overlapping selectors and shorthand/longhand pairs remain conservative compatibility coverage.

Native `.nav-folder-children` hierarchy is never replaced. Its original border-color-only rule remains; no indentation, margins, padding, or positioning is added to that element. Iconic's `.iconic-item` wrapper is left intact. Targeting `.iconic-icon` within native titles preserves absolute `.tree-item-icon` layout. The manufactured caret, folder icon +3px offset, title +30px margin, file icon -14px offset and title +12px margin remain unchanged.

Toolbar geometry stays `left: 24px; width: calc(100% - 48px)`, rather than switching positioning models. Six standard highlight selectors gain case-insensitive matching; their original RGBA colors and normal text color remain. Arbitrary highlight backgrounds are untouched.

No rule can confidently be labeled dead from source inspection alone. Legacy titlebar/vault/ribbon selectors, the root palette and broad SVG inheritance remain pending native visual evidence. No experimental indentation replacement was present. Unusual offsets and `!important` are retained because the theme/plugin cascade requires them.
